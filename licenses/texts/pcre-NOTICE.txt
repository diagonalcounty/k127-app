PCRE 8.45 (2021-06-15)
Source named by the LibGit2-On-iOS v1.3.1 build script: https://github.com/light-tech/PCRE.git
The script clones that repository with no commit pin. Headers inside the
published xcframework identify PCRE 8.45, dated 2021-06-15. The exact git
commit cloned on 2022-07-06 was not recorded.

Statically present inside libgit2.xcframework (https://github.com/light-tech/LibGit2-On-iOS/releases/download/v1.3.1/libgit2.xcframework.zip, checksum 332bfb255649f2295d5530e4abed4e81803acdc6abf18a266695fdb447ca3df2), which
MiniGit (https://github.com/diagonalcounty/MiniGit) revision bc14e1fdbe2eb24cf012a5776ff9759eb21bb174 downloads. The build script builds PCRE as a
static library and libtool -static merges every lib/*.a into libgit2.a.
Headers/pcre.h reports PCRE_MAJOR 8, PCRE_MINOR 45, PCRE_DATE 2021-06-15.
Archive members include pcre_compile.c.o, pcre_exec.c.o, and pcreposix.c.o.

License: BSD terms printed in that shipped pcre.h. Copyright (c) 1997-2014
University of Cambridge. The text below is the license comment from
pcre.h.generic on light-tech/PCRE, which carries the same version macros.

Whether libgit2's objects call this PCRE was not confirmed. libgit2 1.3.1
leaves REGEX_BACKEND empty, and CMake then prefers regcomp_l when that symbol
exists. On Apple that can select the system regex instead of PCRE. The PCRE
license still applies to the PCRE objects shipped in the archive.

libgit2 v1.3.1 COPYING says "The regex library (deps/regex/) is licensed under
the GNU LGPL." Tag v1.3.1 has deps/pcre, not deps/regex. deps/pcre/COPYING only
points at the PCRE distribution's LICENCE and does not include it. The license
used here is the BSD text in pcre.h, not that LGPL paragraph.
